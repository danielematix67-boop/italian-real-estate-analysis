# Reproducibility Guide

## 1. Environment

The project is Python-based and uses a virtual environment for local execution.

Create the environment:

```bash
python -m venv .venv
```

Activate on Linux/macOS:

```bash
source .venv/bin/activate
```

Activate on Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Launch JupyterLab:

```bash
jupyter lab
```

The notebooks are currently configured around a Python 3.13 virtual environment.

## 2. Expected repository layout

The notebooks expect:

```text
data/
├── raw/
│   ├── quotations/
│   ├── transactions/
│   └── population/
└── processed/
    └── benchmark/
```

The processed directory contains analytical hand-off artefacts generated by upstream notebooks.

## 3. Reproducing the quotation workflow

Run:

```text
notebooks/01_01_omi_quotations_dataset_creation.ipynb
```

This discovers semiannual releases, validates filenames and schemas, performs quality checks and writes the processed quotation dataset.

Then run:

```text
notebooks/01_02_omi_quotations_exploration.ipynb
```

This consumes the processed quotation dataset and performs national, regional, municipality and Municipality–Zone analysis.

## 4. Reproducing the transaction workflow

Run:

```text
notebooks/02_omi_transactions_exploration.ipynb
```

The notebook discovers annual OMI transaction releases for 2011–2025, validates the expected table set, harmonises historical schemas and constructs the municipality-year panel.

The workflow validates the `year + codcom` municipality key, join cardinality and unmatched records. Residential NTN size bands are reconciled against the total where applicable.

The resulting processed panel is consumed by Notebook 04.

## 5. Reproducing the population workflow

Run:

```text
notebooks/03_population_exploration.ipynb
```

The notebook inventories annual POSAS releases for 2019–2026, validates the source structure and constructs municipality-level population measures using the official `Età = 999` total row.

## 6. Reproducing the municipality benchmark

Before running Notebook 04, ensure that the processed quotation and transaction artefacts exist.

Run:

```text
notebooks/04_omi_comune_peer_benchmark.ipynb
```

The current default configuration is:

```python
TARGET_COMUNE = "BRESCIA"
LATEST_YEAR = None
PEER_VOL_TOL = 0.50
MIN_PEERS = 8
TOP_N_PROV = 30
MIN_OBS_FOR_RISK = 3
```

With `LATEST_YEAR = None`, the notebook automatically selects the latest year available in the integrated municipality-year panel.

Benchmark outputs are written to:

```text
data/processed/benchmark/
```

The output directory is created automatically if it does not exist.

## 7. Reproducibility controls

The notebooks use several controls to reduce environment-specific behaviour:

- project roots are resolved from repository structure;
- input directories are checked explicitly;
- release files are discovered using documented filename conventions;
- duplicate or unexpected release combinations are surfaced;
- historical schemas are harmonised before panel construction where required;
- joins use explicit keys and cardinality validation;
- unmatched records are reported rather than silently dropped;
- quotation transformations avoid silent imputation;
- benchmark parameters are declared at the top of Notebook 04;
- generated benchmark artefacts are separated from raw source releases.

## 8. Updating the data

When a new official release is added:

1. place the raw release in the appropriate `data/raw/<domain>/` directory;
2. preserve the provider's original naming and file structure where possible;
3. rerun the relevant ingestion or validation notebook;
4. inspect schema, coverage and quality checks;
5. regenerate the processed analytical artefact;
6. rerun the corresponding exploration notebook;
7. rerun Notebook 04 if the quotation or transaction panel changed;
8. review tables and visualisations before committing changes.

## 9. Changing the benchmark target

Notebook 04 is designed to be reusable for other municipalities.

Change:

```python
TARGET_COMUNE = "BRESCIA"
```

and optionally set:

```python
LATEST_YEAR = 2025
```

The peer groups and output filenames are generated from the selected municipality.

The benchmark is only valid when the selected municipality can be resolved in the integrated panel and the required metrics are available.

## 10. Version control

The repository `.gitignore` excludes local virtual environments, notebook checkpoints, temporary files, build artefacts and local configuration.

The notebooks and documentation are the reproducible record of the analytical workflow. Raw source releases and processed artefacts should remain distinguishable so that derived outputs are never treated as the source of truth.
